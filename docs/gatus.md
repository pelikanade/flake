# Gatus

[`modules/services/gatus.nix`](../modules/services/gatus.nix) runs
[Gatus](https://gatus.io) from nixpkgs on `edge`. Its monitors, storage and
status page all come from the YAML document generated by
`services.gatus.settings`, so a monitor set is part of the machine definition
rather than a database the dashboard edits.

## The service

The aspect enables `services.gatus`, binds the web UI to `127.0.0.1:3001` and
keeps history in SQLite at `/var/lib/gatus/data.db`. nixpkgs runs it as the
`gatus` `DynamicUser` with `StateDirectory=gatus` and only `CAP_NET_RAW`, which
the ICMP checks need. No firewall port is opened.

`edge` publishes it with Caddy: the machine maps `status.nvirellia.im` to
`http://127.0.0.1:3001` in `services.caddy.virtualHosts`, so Caddy terminates
public TLS for the status page and Gatus itself never listens off loopback.
Certificate issuance starts once the name resolves to this host.

The instance runs on the public VPS instead of the machine it mostly monitors, so
a failure that takes neko-sphere's advertisement down still shows on the page.
The trade-off is that checks of neko-sphere's loopback listeners — the NetBird
tunnel and sing-box — do not travel with it.

## Endpoints

`edge` declares three groups:

| Endpoint | Group | Check |
| --- | --- | --- |
| Freezer | Neko Sphere | `http://nsphere-freezer.dwelf-hoki.ts.net/`, `[STATUS] == 200` |
| Magpie gateway | Neko Sphere | `http://nsphere-magpie-api.dwelf-hoki.ts.net/v1/models`, `[STATUS] == 401` |
| Magpie UI | Neko Sphere | `http://nsphere-magpie.dwelf-hoki.ts.net/`, `[STATUS] == 401` |
| Paseo daemon | Neko Sphere | `http://nsphere-paseo.dwelf-hoki.ts.net/api/health`, `[STATUS] == 200` |
| nvirellia.im | Noa's IVs | `https://nvirellia.im/`, `[STATUS] == 200` |
| nuts.nvirellia.im | Noa's IVs | `https://nuts.nvirellia.im/`, `[STATUS] == 200` |
| SSH | Edge | `tcp://127.0.0.1:22`, `[CONNECTED] == true` |
| Gatus | Edge | `http://127.0.0.1:3001/`, `[STATUS] == 200` |

The default interval is 60 seconds. Add an endpoint in the machine definition:

```nix
services.gatus.settings.endpoints = [
  {
    name = "Example";
    group = "Edge";
    url = "http://127.0.0.1:1234/health";
    interval = "30s";
    conditions = [ "[STATUS] == 200" ];
  }
];
```

Each entry is Gatus' own endpoint shape, so conditions such as
`[RESPONSE_TIME] < 500`, `[BODY].status == UP`, certificate expiry and
`client.insecure` are available without a repository-level abstraction.

A TCP endpoint uses the `tcp://` scheme and `[CONNECTED] == true`; `[STATUS]`
does not apply to it. Magpie's UI returns `401` without its sign-in key, so its
condition accepts exactly that code.

## Verification

```sh
systemctl status gatus
curl -s http://127.0.0.1:3001/api/v1/endpoints/statuses \
  | jq -r '.[] | [.key, (.results[-1].success | tostring)] | @tsv'
tailscale serve status
journalctl -u gatus -b --no-pager
```

The status page is at `https://status.nvirellia.im/` once the name resolves to
`edge`.
